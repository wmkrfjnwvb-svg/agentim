## 2. 实施顺序

每个阶段结束时，Linux 和 Windows 上的全部测试都要通过，压测和崩溃测试不能退化。

| 阶段 | 内容 | 状态 |
|---|---|---|
| **P1 基础** | Windows CI 矩阵；崩溃测试改写为 Rust（跨平台）；结构化日志与指标；存储抽象 + 三种数据库的一致性测试；组提交 + 故障注入测试 + 性能门槛；多库路由（控制库、会话目录、每个库一个写线程、跨库查询合并、按库的健康检查、单元迁移工具） | ✅ 完成。未完成项：告警规则和面板、在线迁移的管理接口、systemd 和 Docker 打包 |
| **P1.5 性能** | D11 | 待确认 |
| **P2 安全** | 账号密码、OIDC、Agent API Key、令牌只存哈希；内置 TLS、Origin 校验；静态加密（D3）；信息屏障与每个单元独立密钥（企业版） | 待开始 |
| **P3 审批与工具** | 审批 v2（D5）；工具网关 v1（D6）；富消息（按钮、卡片） | 待开始 |
| **P4 合规** | AI 内容标记；举报、拉黑、审核队列、处置记录；导出、删除、保留策略、法律保全（D7） | 待开始 |
| **P5 客户端** | PWA + 桌面通知；Tauri 2 Windows 客户端；TypeScript SDK | 待开始 |
| **P6 集群** | Raft 选型（ADR-2）；网关、Router、分片拆分；用户收件箱；大群模式 | 待开始 |
