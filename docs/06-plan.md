| # | 事项 | 我的建议 |

| D30 | 病毒扫描 | M5 只做扫描钩子（可接 ClamAV），不内置扫描器；扫描服务出错时默认**拒绝**引用（安全优先，可配置为放行） |

客户端 SDK 和 AI 组件的调研见 [research/sdk-and-ai-2026.md](research/sdk-and-ai-2026.md)，设计见 [05 §6](05-operations.md) 和 [03 §9](03-ai-native.md)，以下几点需要你决定：

| # | 事项 | 我的建议 |
|---|---|---|
| D31 | SDK 本地存储的默认级别 | **人用的客户端和 Agent 都默认 `full`**（会话、成员、消息、待发送队列、草稿、设置都存 SQLite；按你的意见：Agent 每轮都要读历史做上下文，不存就会反复拉垮服务端）；Agent 多实例时各存一份缓存，或接团队自己的数据库共用；只有无状态的一次性程序显式选 `none` |
| D38 | 服务端读取限流（兜底） | 现在服务端只限制 Agent 发消息，**读历史（pull）没有限制**，写得不好的客户端或 Agent 仍可能把服务端拉垮。建议按连接（令牌桶）限制拉取次数和条数，Agent 比人更严，超限返回 `rate_limited` 并带重试时间；SDK 收到后按时间重试。和 SDK 一起放在 M7 |
| D39 | **只同步、不读历史**（你提出，还在斟酌） | 服务端为每台设备记一个同步位置，设备只能从这个位置往后拿，拿到并存好后确认，位置才前进（这样设备崩溃也不丢）；不再提供"按 seq 随便读历史"的接口，每条消息每台设备只下发一次，从结构上避免被反复拉取拉垮。需要一起定的：① 新设备、重装、浏览器数据被清掉、Agent 本地库丢失时怎么办（完全没有历史，像 WhatsApp；或者只给每个会话最近 N 条）；② 新成员能否看到加入前的消息（现在人可以、Agent 不可以）；③ 开放 API 的历史查询（开发者后端用）和 GDPR 数据导出是否保留；④ 服务端的日志保留多久（所有设备都确认后能否删，举报审核和审计需要保留一段时间）。见下方说明 |
| D32 | 本地数据的加密方式 | SDK 核心按值加密（AES-256-GCM，和服务端同一套代码），钥匙放系统安全存储（钥匙串、Keystore、DPAPI）；**默认开启**。不用 SQLCipher：浏览器上用不了，还要额外的编译依赖 |
| D33 | 浏览器端的本地存储 | SQLite wasm + OPFS（在 Worker 里，多标签页只有一个写），不支持时退回 IndexedDB；这样网页端和原生端用同一份表结构和同步逻辑 |
| D34 | 大缺口阈值、待发送有效期 | 缺口超过 300 条直接跳到最新、往回翻时再补（同 Sendbird）；待发送的消息 72 小时后变为"已过期"失败，由用户决定重发（Sendbird 3 天、Stream 12 小时） |
| D35 | M6（AI 核心组件）的范围和顺序 | 按调研调整：① Agent 注册、独立凭据、**必须有人类负责人**；② 暂停 / 急停；③ **"请人决定" + 待办收件箱**（把现有草稿审批扩展成通用的"Agent 请人批准 / 回答 / 选择"，多人、持久、只有一个决定生效，人不在线时推送）——这是调研发现海外最大的空白；④ 任务 + 进度事件；⑤ MCP 服务（按 2026-07-28 新规范）；⑥ 用量和成本计量；⑦ OpenTelemetry 导出；⑧ 记事本做精简版（只做治理，不和 Mem0 等比检索）。A2A 网关仍在 MVP 2 |
| D36 | AI 标记（EU AI Act 第 50 条，**2026-08-02 已生效**） | 现有的 `sender_type` 已满足基本要求；补上"被批准的草稿记录批准人和是否修改、仍算 AI 生成"、流式回复从开始就带标记；客户端默认显示 AI 标识，**不提供关闭开关**。放进 M6 |
| D37 | AI 消息体验：转人工、结构化消息（卡片 / 按钮 / 表单）、引用来源、点赞点踩反馈 | 调研中各家都有、我们计划里没有。建议放在 M6 之后紧接着做（M6 已经比较大）；如果你希望 M6 一起做，M6 会多出约三分之一的工作量 |

## 2. MVP 实施顺序（D16 已确认）

原则：先让开发者能真正用起来，差异化（Agent 治理 + AI 核心组件）放进第一版；最重的端到端加密和其余语言 SDK 放第二版。每一步结束时，Linux 和 Windows 上的全部测试（场景测试、并发测试、压测、崩溃测试）都要通过，不能退化。
