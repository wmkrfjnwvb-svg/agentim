- AgentIM：管理 API 和管理系统、OIDC；生态桥（ChatKit、Vercel Chat SDK、Agno、AG-UI）、主题 / 广播、协调者 Agent、服务端托管 Agent；OpenTelemetry 导出；完整 Web 端、Windows 端、原生手机 App 和离线推送。
- 企业版（收费点，D70）：授权机制；SAML / SCIM / LDAP、BYOK、按单元密钥、信息屏障、多库隔离；E2EE 组织策略；法律保全、eDiscovery、审计导出、组织级保留策略、DSA 报告；审核后台；多级审批、工具策略编辑器、跨团队观察。

**E. 之后**

写入性能优化（目标每节点 1 万条/秒）；WASM 插件；Android、iOS、C++、Go 客户端 SDK；托管云。

## 3. 建议的 MVP 顺序（D66，待确认）

| 顺序 | 内容 | 理由 |
|---|---|---|
| 1 | A1 工具网关 + 审批 + 远程审批 + 手机网页 | 你定的核心价值；"用手机管住 Claude Code / Codex"是最直观的演示 |
| 2 | A3 搜索过滤、B4 加密关闭修正 | 小，顺手做掉 |
| 3 | A2 A2A 网关 | 第二个核心价值；外部 Agent 能接进来 |
| 4 | A5 CLI 拆分 + 管理 API 的第一部分 | 后面 GDPR、文件的管理命令都挂在管理 API 上 |
| 5 | A4 GDPR 和审查的基础部分 | 依赖管理 API；海外上线前必须有 |
| 6 | A6 文件和图片 | D27–D30 确认后 |
| 7 | A7 客户端 Rust 核心 SDK → A8 E2EE | E2EE 只能在客户端加解密 |
| 8 | A9 部署和发布 | 第一个公开版本之前 |

集群（§2 C）在 D69 确认后插入，建议放在第 4 步之后，因为它会改动连接、缓存、推送这些底层，越早做，后面的功能越少返工。

每一步结束时，Linux 和 Windows 上的全部测试（场景、并发、压测、崩溃）都要通过，不能退化。
