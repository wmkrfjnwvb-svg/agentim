## 2. 实施顺序

每个阶段结束时，Linux 和 Windows 上的全部测试都要通过，压测和崩溃测试不能退化。

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P1 基础** | Windows CI 矩阵；崩溃测试改写为 Rust（跨平台）；结构化日志与指标；存储抽象（D2）+ 三种后端的一致性测试；组提交（D1）+ 故障注入测试 + 性能门槛 | D1、D2、D9 |
| **P2 安全** | 账号密码、OIDC、Agent API Key、令牌只存哈希；内置 TLS、Origin 校验；静态加密（D3） | D3 |
| **P3 审批与工具** | 审批 v2（D5）；工具网关 v1（D6）；富消息（按钮、卡片） | D5、D6 |
| **P4 合规** | AI 内容标记；举报、拉黑、审核队列、处置记录；导出、删除、保留策略、法律保全（D7） | D7 |
| **P5 客户端** | PWA + 桌面通知；Tauri 2 Windows 客户端；TypeScript SDK | D8 |
| **P6 集群** | Raft 选型（ADR-2）；网关、Router、分片拆分；用户收件箱；大群模式 | P1 |
