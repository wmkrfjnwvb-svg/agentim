## 2. MVP 实施顺序（待确认，D16）

原则：先补"用户一上手就会碰到"的缺口（成员管理、账号、设备、加密），再做 SDK 和客户端，AI 核心组件尽早进来，审批 v2 和工具网关按你的要求放最后。每一步结束时，Linux 和 Windows 上的全部测试（含场景测试、并发测试、压测、崩溃测试）都要通过，不能退化。

| 步骤 | 内容 | 依赖 |
|---|---|---|
| **M0** | D11：单机全部性能数据（3 种数据库 × 写入 / 扇出 / 长连接 / 大群 / 慢客户端 / 恢复时间）写进 README | — |
| **M1** | D12：成员生命周期（移除、退出、转让、解散）、拉黑、用户目录只看得到该看的人；配套场景测试和并发测试 | — |
| **M2** | 账号与设备（D14 前半）：账号密码 + TOTP、OIDC；每台设备独立令牌、设备列表、单台下线、已读多端同步、新设备登录通知；令牌只存哈希；内置 TLS、Origin 校验；静态加密默认开启（D3）；管理 API（`/admin/v1`） | M1 |
| **M3** | Rust 核心 SDK + E2EE（D4）：连接、重试与去重、同步引擎、本地存储、MLS（OpenMLS）；服务端的 KeyPackage 目录和 MLS 投递 | M2 |
| **M4** | AI 核心组件第一步（D15 §9.7 的 A）：Agent 注册与身份、任务、Agent 记事本、Agent 管理（暂停、权限、预算）、MCP 服务 | M2 |
| **M5** | 管理系统（D14 后半）：Go + React，一个二进制启动 | M2、M4 |
| **M6** | SDK 各语言绑定 + 构建脚本（D8）；Windows 客户端（Tauri 2） | M3 |
| **M7** | 合规（D7）：举报、审核队列、处置记录、导出、删除、保留策略；AI 内容标记 | M2、M5 |
| **M8** | AI 核心组件第二步：A2A 网关（同一服务器内外的 Agent 互通） | M4 |
| **M9** | 审批 v2（D5）、工具网关（D6）、富消息 | M4 |
| MVP 之后 | 跨互联网 Agent 联邦（D15 §9.7 的 C）；集群（Raft、网关拆分、用户收件箱、大群模式）；离线手机推送 | |
