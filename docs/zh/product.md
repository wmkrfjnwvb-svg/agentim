# 产品

## 1. AgentIM 是什么

AgentIM 让 AI 在你的产品里安全地办事。它是内置了 AI Agent 的聊天基础设施：
- 人和 Agent 在同一个会话里交流；
- Agent 调用企业的 API 和 MCP 服务；
- 会改数据的操作由人批准；
- 任何人随时可以接手，每一步都有记录。

它是一个开源程序 `agentim`（Apache 2.0），单机或集群都能跑，支持 SQLite、PostgreSQL、MySQL；另有托管云。

和别的方案不同在：

- **持久、有序、多方共享的会话。** 会话的记录连续、有序，人和多个 Agent 共享。Agent SDK 里的"会话"只是一个人和一个 Agent 的一次运行；AgentIM 的会话不随运行、框架、机器的变化而断。
- **治理是协议的一部分。** 审批、请人决定、接管、急停、预算、护栏、审计、AI 标识都在服务端里，不需要应用自己再加一层。
- **Agent 能搬走，也能干净地结束。** Agent 的历史和状态在服务端，换一把密钥就能在别的机器、别的框架上接着干；销毁时吊销密钥、断开连接、删除状态并销毁数据密钥。
- **一个程序，全部功能免费。** 从笔记本到集群是同一个程序，数据归部署的人。

## 2. 用户和场景

AgentIM 给开发者，以及做产品的团队和集成商用：

| 用户 | 典型用法 |
|---|---|
| 创业团队、独立开发者 | 给自己的产品加聊天和 AI 助手；做 AI 原生的客服、社交、协作产品 |
| SaaS 团队 | 在已有产品里加聊天和助手 |
| 集成商 | 给客户搭助手 |
| Agent 开发者 | 让 Agent 在会话里和人、和别的 Agent 协作 |

先做两个场景：

- **A. 会办事的助手。** 助手在产品里调企业的 API：查订单、退款、改地址、预约。会改数据的调用要人批准；办不了或用户要求时转给人。端到端演示见[售后示例](../../examples/)。
- **D. 双方之间的 AI 协助。** 在市场、咨询、预约平台上，AI 帮一方查资料、先拟回复由真人发出、传私下的提示。见[顾问示例](../../examples/)。

## 3. 核心保证

每个改动都必须守住。每个设计页说明这个板块怎么守住它们。

| 编号 | 保证 | 怎么验证 |
|---|---|---|
| G1 | **稳定**：节点故障不影响正确性；过载时拒绝请求，而不是耗尽内存 | 故障注入、杀进程测试、带慢客户端的规模测试 |
| G2 | **不丢消息**：已确认的消息在崩溃、重启、节点故障、数据库切主后都在。写入持久化之后才确认 | Linux 和 Windows 上流量中 `kill -9`；提交失败不能确认；切主测试 |
| G3 | **有序**：会话里所有成员看到同一个连续的序列；同一设备发的消息按发送顺序提交 | 每个测试都检查序号连续、推送有序 |
| G4 | **业务正确**：权限、可见性、审批、去重由服务端强制，客户端绕不过去 | 三种数据库上的业务场景和并发测试；`agentim verify` 回放日志 |
| G5 | **高并发**：单节点数万连接，没有全局序号器和全局锁 | 压测和规模测试 |
| G6 | **集群**：单机到多节点同一个程序、同一套协议；上集群不改协议 | 带故障的多节点测试 |

## 5. 目标和实测

| 指标 | 目标 | 实测 |
|---|---|---|
| 单节点写入吞吐 | 1 万条/秒（NVMe） | 每个库约 1,100–1,300 条/秒。上限来自每条 SQL 语句的固定开销（[架构 §5](architecture.md#5-写入路径)） |
| 未饱和时的确认延迟 | p99 < 20 ms | 10 个客户端：p99 13 ms |
| 同地域端到端投递 | p99 < 200 ms | 2 万连接、每秒 200 条：p99 7 ms；2000 人大群、每秒 10 万次推送：p99 43 ms |
| 已确认消息的持久性 | `kill -9`、断电、数据库切主都不丢 | `kill -9`（Linux、Windows）、提交失败、切主都验证过 |
| 节点故障后恢复 | 客户端几秒内恢复 | 崩溃节点的分片约 15–18 秒后被接手（租约 15 秒）；期间这些会话的写入暂停 |
| 连接数 | 集群 100 万 | 单节点测过 2 万，含同时重连（每连接约 13 KB） |
| 慢客户端 | 不能影响别人 | 已验证：慢客户端只丢自己的推送，并被通知重新同步 |
| 纯人类会话的 AI 开销 | 0 | 0 |

数据上限：单条消息最多 64 KB；单条流式消息最多 256 KB、10 分钟；每个 Agent 在每个会话里最多 2 路并发流。

完整的压测表在 [README](../../README.md#performance)。

## 6. 不做的

- 模型推理和模型网关。内置助手调用模型厂商，AgentIM 不托管模型。
- 通用的 Agent 运行时：沙箱、工作流引擎、记忆检索。Agent 在自己的框架里跑，作为成员接进来。
- 全局的消息顺序。顺序只在会话内。
- 暂不做：端到端加密、语音和视频通话、原生桌面和手机 App。AgentIM 提供服务端、协议、SDK 和界面组件。
