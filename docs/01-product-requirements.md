# 01 产品需求

> 状态：草案 v0.1（2026-10-10）

## 1. 产品定位

**AgentIM 是一套开源、AI 原生、用 Rust 实现的 IM 底层框架。** 优先面向海外市场。

一句话定位：**个人免费、企业可控、AI 原生。**

| 支柱 | 面向谁 | 核心承诺 |
|---|---|---|
| 个人免费 | 开发者、个人、小团队 | 全部消息能力和 AI 交互能力免费，不限人数、不限规模 |
| 企业能力 | 组织 | 身份、合规、审计、高可用、服务 |
| AI 能力 | 两者 | AI 可以和任何人、任何 AI 交流；人可以随时介入、过滤、监控 |

### 1.1 为什么做

- 海外 IM 市场正在从"在 IM 里加 AI"转向"AI Agent 是 IM 的一等公民"（Slack、Telegram、WhatsApp、Stream、Ably 等都在推进，详见[调研文档](research/market-and-competitors.md)）。
- 商业 SaaS（Stream、Sendbird、Ably）闭源；开源 IM（Matrix、Rocket.Chat、Mattermost、OpenIM）的 AI 能力主要在应用层外挂，消息模型本身没有为流式输出和 Agent 设计。
- **空位：开源 + 可自托管 + 协议层 AI 原生 + 大群流式。**

### 1.2 不做什么

- 不在 IM 内部运行大模型。Agent 作为特殊客户端接入，IM 负责传输、权限、计量和治理。
- 不做全局消息顺序，只保证会话内有序。
- 不做独立的终端用户聊天 App 作为第一优先级（先做框架 + SDK + 参考客户端）。

## 2. 目标用户

| 用户 | 典型场景 | 使用版本 |
|---|---|---|
| 独立开发者 | 给自己的产品加聊天和 AI 助手 | 社区版单机 |
| 创业团队 | 构建 AI 原生的社交、客服、协作产品 | 社区版集群 |
| 企业 IT / 平台团队 | 内部自托管 IM + AI Agent，需要合规与管控 | 企业版 |
| AI Agent 开发者 | 让 Agent 与人、与其他 Agent 在会话中协作 | 两者 |

## 3. 核心需求

### 3.1 四个硬性要求

| 编号 | 要求 | 验收标准 |
|---|---|---|
| R1 | **稳定** | 任一非存储节点宕机不影响消息正确性；存储分片少数派故障自动恢复 |
| R2 | **不丢消息** | 发送方收到 ACK 的消息，在多数派存活时永不丢失；离线用户上线后可完整补齐 |
| R3 | **支持群发** | 单群上限 10 万人，默认 100–1000 人；大群推送合并，不造成下行风暴 |
| R4 | **消息顺序** | 同一会话内所有成员看到的顺序一致；同一发送方的消息按发送顺序呈现 |

### 3.2 规模要求

- 百万级并发长连接。
- 集群可水平扩展，无单点瓶颈（无全局序号器、无全局锁）。
- 单机模式与集群模式使用同一个二进制，从单机升级到集群无需数据迁移。

### 3.3 AI 原生要求

| 编号 | 要求 |
|---|---|
| A1 | Agent 是一等身份，可作为单聊、群聊成员，可被 @、可主动发言 |
| A2 | 流式消息：可追加内容、合并推送、断线续传、加载历史时得到完整消息 |
| A3 | 取消、打断、并发轮次 |
| A4 | 工具调用和结果作为消息事件 |
| A5 | 带权限的历史/上下文检索 API |
| A6 | 内置 MCP Server；后续支持 A2A 互通 |
| A7 | 人工介入：观察、耳语、审批、打断、接管、撤回/修订 |
| A8 | 过滤：进入 AI 前、AI 输出后、流式过程中 |
| A9 | 监控：实时面板、会话回放、审计、告警 |
| A10 | 安全护栏：跳数上限、速率与预算上限、循环熔断、注入检测（免费版即具备） |

详见 [03 AI 原生能力](03-ai-native.md)。

### 3.4 部署要求

- 开源版：一个二进制、一条命令启动，单机模式内置存储。
- 集群模式：同一二进制按角色启动（gateway / shard / push / agent-gw）。
- 支持多租户：`tenant_id` 从第一天起进入消息模型和分片键，为未来托管云预留。

## 4. 非功能指标（初始目标，待压测确认）

| 指标 | 目标 |
|---|---|
| 并发连接 | ≥ 100 万（集群） |
| 单网关节点连接数 | ~15 万 |
| 消息写入峰值 | ≥ 5 万条/秒（集群） |
| 端到端投递延迟（同地域，P99） | < 200ms |
| 已 ACK 消息持久性 | 多数派存活即不丢 |
| 纯人类会话的额外延迟（AI 钩子） | 0（默认不挂载） |

## 5. 商业模式

- 协议：**Apache 2.0**（专利授权条款对海外企业法务更友好）。
- 模式：**开源核心（Open Core）**。开源版功能完整、不限规模；企业版对"组织才需要的能力"收费。
- Apache 2.0 无法通过协议约束企业付费，企业付费依赖企业功能、服务和未来托管云。
- 详见 [04 版本划分](04-editions.md)。
