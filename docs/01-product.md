# 01 产品

> 当前有效的产品定义（2026-10-18）。进度和待定事项见 [06](06-plan.md)。

## 1. 定位

**AgentIM：给开发者的、AI 原生的聊天基础设施。** 开发者把聊天和 AI 助手嵌进自己的产品；任何框架写的 Agent（OpenAI Agents SDK、Claude Agent SDK、LangGraph、Vercel AI SDK……）都能通过 MCP、Agent API 或 Agent SDK 作为会话成员接进来（[03](03-agents.md)）。

- **持久、有序、多方**：每个会话的记录连续不丢、有顺序，人和多个 Agent 共享；Agent SDK 自带的"会话"只是一个人对一个 Agent 的一次运行。
- **可治理**：审批、请人决定、接管、急停、预算、护栏、审计、AI 标记都是协议原语，不是应用层外挂。这是和 Stream、Sendbird 等聊天 SDK 的区别，也是和 Tuwunel、OpenIM 等开源 IM 的区别。
- **秒迁移，随时销毁**：Agent 的历史和状态在服务端，签发新凭据就能换机器、换框架接着干；一键销毁会吊销凭据、断开连接、删除它的状态并销毁数据密钥。
- **一个程序**：`agentim` 单机到集群同一个程序，可自托管，数据归开发者；全部功能免费；优先面向海外。

## 2. 用户与场景

只服务开发者。

| 用户 | 典型场景 |
|---|---|
| 独立开发者、创业团队 | 给自己的产品加聊天和 AI 助手；AI 原生的社交、客服、协作产品 |
| SaaS 团队 | 在已有产品里加聊天和 AI 助手 |
| 集成商、外包团队 | 给客户搭建带聊天和 AI 助手的产品 |
| Agent 开发者 | 让 Agent 与人、与其他 Agent 在会话中协作 |

首要场景：带转人工的 AI 客服窗口；人和 Agent 一起工作的团队群聊；多个 Agent 协作的房间（也是三个示例应用，[12 §5](12-developer-experience.md)）。

## 3. 核心保证（所有改动都必须守住）

| 编号 | 保证 | 验收标准 |
|---|---|---|
| G1 | **稳定** | 任一无状态节点宕机不影响正确性；存储少数派故障自动恢复；过载时拒绝请求，而不是耗尽内存 |
| G2 | **不丢消息** | 收到 ACK 的消息，在存储多数派存活时永不丢失。ACK 只在数据持久化（fsync）之后发出 |
| G3 | **消息有序** | 会话内所有成员看到同一顺序，seq 连续无空洞；同一设备发出的消息按发送顺序提交 |
| G4 | **业务正确** | 权限、可见性、审批、去重在服务端强制执行，客户端不可绕过 |
| G5 | **高并发** | 单机万级消息/秒；集群百万级长连接，可水平扩展，无全局序号器和全局锁 |
| G6 | **集群** | 单机与集群使用同一个二进制和同一套协议；单机升级到集群无需改协议 |

每个设计都要附一张"对 G1–G6 的影响"表（见 [02 架构](02-architecture.md) §8）。

## 5. 非功能指标

| 指标 | 目标 | 当前实测 |
|---|---|---|
| 单机写入吞吐 | ≥ 10,000 条/秒（NVMe） | 约 1,100–1,300 条/秒（单库）；瓶颈是每条 SQL 语句的固定开销（[02 §4.8](02-architecture.md)） |
| 单机 ACK 延迟 | p99 < 20ms（低于饱和负载时） | 10 个客户端 p99 13ms；50 个客户端同群 p99 68ms |
| 端到端投递延迟（同地域，P99） | < 200ms | 2 万连接、200 条/秒时 p99 7ms；2000 人大群、每秒 10 万次推送时 p99 43ms（[05 §5.4](05-operations.md)） |
| Agent 首个 token 到客户端 | P99 < 150ms | 未测 |
| 已 ACK 消息持久性 | `kill -9`、断电、数据库切主后都不丢 | `kill -9` 在 Linux 和 Windows 上验证；提交失败不发 ACK（故障注入）；切主测试见 [11](11-cluster.md) |
| 节点故障后恢复 | 客户端 P99 在 10 秒内恢复收发 | 崩溃节点的分片约 15–18 秒后由其他节点接手（租约 15 秒），这些会话的写入在此期间暂停 |
| 并发连接 | 集群 ≥ 100 万 | 单机已测 2 万（含同时重连，每连接约 13KB）；百万级未测 |
| 慢客户端不影响他人 | 只丢自己的推送并收到 resync | 已验证 |
| 纯人类会话的 AI 钩子开销 | 0 | 0 |

数据上限：单条消息 ≤ 64KB；单条流式消息 ≤ 256KB、最长 10 分钟；每个 Agent 在每个会话内最多 2 路并发流。

## 6. 一个程序

只有一个产品、一个程序 `agentim`：服务、运维命令、开发者控制台都在里面，单机到集群不换程序，没有社区版和企业版之分。

## 7. 收费和竞品

代码 Apache 2.0，全部功能免费，不限人数和规模（含集群）。收入来自托管云和自托管用户的付费支持。托管云按**合并后的消息**计费（一条流式 AI 消息只算一条），Agent 不按月活计费；建议免费每月 1 万条、Pro 每月约 49–99 美元（D102，和设计伙伴聊过再定）。`tenant_id` 已经在数据模型里。

**同行价格**（2026-10 官网公开价，可能已变）：Stream 免费 1,000 月活、100 并发，付费 Start 399 美元/月、Elevate 599 美元/月（按年付）；Sendbird 试用 1,000 月活、20 并发，Starter 349 美元起、Pro 499 美元起，并发被卡在月活的 5–10%，AI 业务已转向客服（delight.ai）；CometChat 聊天和音视频打包、价格较低；Ably AI Transport 按发布的消息而不是 token 计费。三家都是闭源云服务（Sendbird、CometChat 只在企业合同里可自托管）；OpenIM 开源可自托管，但没有 UI 和账号体系。

**开发者的痛点**：按月活和并发计费，费用难预估（中型用户每年约 4 万–15 万美元）；只能用云，数据不在自己手里、难迁移；开源方案要自己补 UI 和登录。

**开发者选型看的**（多家资料一致）：令牌由自己的后端签发（✅）；服务端 API 和 SDK（✅）；客户端 SDK 的离线队列和重连质量（P2）；可换主题、可替换的 UI 组件（P3，选型关键）；发送前拦截、自定义字段、Webhook（✅）；十分钟教程、示例应用、免费开发额度（P5、P6）；从其他厂商导入数据（D107）；离线推送（Web Push、APNs、FCM）和审核。

## 8. 风险

- Apache 2.0 允许任何人托管本项目。护城河来自迭代速度、开发者体验、托管云和服务，而不是代码本身。
- "自托管 + Agent 治理"是不是开发者真正的购买理由，还没有用户数据；靠设计伙伴验证（[06 §4](06-plan.md)）。
- 写入吞吐离目标还差约一个数量级（§5）。

## 9. 不做

- 不在 IM 内部做模型推理，不做模型网关（LiteLLM、Portkey 已成熟）；Agent 可以上报模型用量。
- 不做 Agent 中间件：工具网关、审批 v2、Claude Code / Codex 远程审批、A2A 网关和跨服务器联邦、服务端托管 Agent、Agent 循环、记忆检索、沙箱、工作流引擎。
- 不做企业版功能：SAML、SCIM、客户自管密钥、法律保全、电子取证、DSA 报告、信息屏障、授权文件。
- 不保证全局消息顺序，只保证会话内有序。
- 暂缓：端到端加密、语音视频通话、原生桌面端和手机 App（先交付服务端、协议、SDK 和组件）。
