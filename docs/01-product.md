# 01 产品

> 版本 v0.3（2026-10-10）。本文是当前有效的产品需求。早期草案中被评审推翻的内容已经删除，历史版本见 git 记录。

## 1. 定位

**AgentIM：把 Agent 治理做进消息协议的开源 IM 底层框架。** 单二进制部署，免费版自带安全护栏，优先面向海外市场。

| 支柱 | 面向谁 | 核心承诺 |
|---|---|---|
| 个人免费 | 开发者、个人、小团队 | 全部消息能力和 AI 交互能力免费，不限人数、不限规模 |
| 企业可控 | 组织 | 身份、合规、审计、加密、高可用、服务 |
| AI 原生 | 两者 | AI 可以与任何人、任何 AI 交流；人可以随时介入、审批、过滤、监控。长期目标：成为 AI 之间、AI 与人之间沟通协作的底层组件，包括跨组织、跨服务器的 Agent 通信（[03 §9](03-ai-native.md)） |

**差异化在 Agent 治理，不在"开源"或"Rust"。** 开源的 Rust IM 已经存在，例如 Tuwunel（Rust 写的 Matrix 服务端，Apache-2.0，瑞士政府资助）。OpenIM 也在宣传 AI 网关。我们的独特之处是：Agent 身份、审批、介入、护栏、工具权限、审计都是**协议原语**，而不是应用层外挂。竞品详情见[调研](research/market-and-competitors.md)。

不做的事情：

- 不在 IM 内部运行大模型。Agent 作为特殊客户端接入，IM 负责传输、权限、计量和治理。
- 不保证全局消息顺序，只保证会话内有序。
- 第一优先级不是终端聊天 App。先交付服务端、协议、SDK 和参考客户端（Web，之后是 Windows 桌面端）。

## 2. 目标用户与首要场景

**首要场景：AI 客服 / AI 助手接入现有产品。** 这个场景同时用到人机会话、审批、接管、工具调用和监控，最能体现差异化，也最容易收费。

| 用户 | 典型场景 | 版本 |
|---|---|---|
| 独立开发者 | 给自己的产品加聊天和 AI 助手 | 社区版单机 |
| 创业团队 | AI 原生的社交、客服、协作产品 | 社区版 |
| 企业 IT / 平台团队 | 自托管 IM + Agent，需要合规、加密、审批 | 企业版 |
| Agent 开发者 | 让 Agent 与人、与其他 Agent 在会话中协作 | 两者 |

**待做：用户验证。** 在写集群代码之前，访谈 10–20 位目标开发者（AI 客服、AI 社交、企业内部 Agent 平台三类），验证"自托管 + Agent 治理"是否真是购买理由。

## 3. 核心保证（所有改动都必须守住）

| 编号 | 保证 | 验收标准 |
|---|---|---|
| G1 | **稳定** | 任一无状态节点宕机不影响正确性；存储少数派故障自动恢复；过载时拒绝请求，而不是耗尽内存 |
| G2 | **不丢消息** | 收到 ACK 的消息，在存储多数派存活时永不丢失。ACK 只在数据持久化（fsync）之后发出 |
| G3 | **消息有序** | 会话内所有成员看到同一顺序，seq 连续无空洞；同一设备发出的消息按发送顺序提交 |
| G4 | **业务正确** | 权限、可见性、审批、去重在服务端强制执行，客户端不可绕过 |
| G5 | **高并发** | 单机万级消息/秒；集群百万级长连接，可水平扩展，无全局序号器和全局锁 |
| G6 | **集群** | 单机与集群使用同一个二进制和同一套协议；单机升级到集群无需改协议 |

每个设计都要附一张"对 G1–G6 的影响"表（见 [02 架构](02-architecture.md) §8）。

## 5. 非功能指标

| 指标 | 目标 | 当前单机版实测 |
|---|---|---|
| 单机写入吞吐 | ≥ 10,000 条/秒（NVMe） | 约 1,100–1,300 条/秒（单 SQLite 库）。fsync 已不是瓶颈，现在的瓶颈是每条 SQL 语句的固定开销，见 [02 §4.8](02-architecture.md) |
| 单机 ACK 延迟 | p99 < 20ms（低于饱和负载时） | 10 个客户端时 p99 13ms；50 个客户端同群时 p99 68ms |
| 端到端投递延迟（同地域，P99） | < 200ms | 单机（CI）：2 万连接、200 条/秒时 p99 7ms；2000 人大群、每秒 10 万次推送时 p99 43ms（[05 §5.4](05-operations.md)） |
| Agent 首个 token 到客户端 | P99 < 150ms | 未测 |
| 已 ACK 消息持久性 | `kill -9` 和断电后都不丢 | `kill -9` 已在 Linux 和 Windows 上验证；提交失败时不发 ACK 已验证（故障注入） |
| 网关故障后恢复 | 客户端 P99 在 10 秒内恢复收发 | 集群阶段验证 |
| 并发连接 | 集群 ≥ 100 万 | 单机已测 2 万，含 2 万连接同时重连（每个连接约 13KB 服务端内存）；百万级在集群阶段验证 |
| 慢客户端不影响他人 | 慢客户端只丢自己的推送并收到 resync | 已验证（[05 §5.4](05-operations.md)） |
| 纯人类会话的 AI 钩子开销 | 0 | 0（钩子只在 Agent 路径上） |

数据上限：单条消息 ≤ 64KB；单条流式消息 ≤ 256KB、最长 10 分钟；每个 Agent 在每个会话内最多 2 路并发流。

## 6. 版本划分

原则：**开发者能用到的全部开源；只有"组织"才需要的能力收费。** 社区版按功能分层，不设规模限制。安全护栏和基础合规工具属于基础能力，免费版就有。

| 能力 | 社区版（Apache 2.0） | 企业版（商业授权） |
|---|---|---|
| 消息核心 | 全部，单机到集群，不限规模 | 同左，另加多地域、零停机升级 |
| AI 原生 | 流式、Agent 成员、工具网关、MCP、护栏 | 同左 |
| 审批 | 所有者审批、代理审批人、规则路由、审批收件箱 | 多级审批、按风险路由到审批组、审批 SLA 报表 |
| 介入 | 所有者管理自己的 Agent | 主管跨团队观察、耳语、接管 |
| 工具权限 | 按 Agent 授权、参数规则、审批 | 按用户/组/团队授权、委托权限、工具策略编辑器 |
| 身份 | 账号密码、OIDC、2FA、Agent API Key | SAML、SCIM、LDAP、细粒度管理员角色 |
| 加密 | TLS、默认开启的静态加密、端到端加密（MLS） | 客户托管密钥（AWS KMS、GCP KMS、Azure Key Vault、Vault）、按单元禁用 E2EE |
| 合规 | 举报、拉黑、审核队列、导出、删除、保留策略、AI 披露 | 法律保全、eDiscovery、审计导出到 SIEM、DSA 透明度报告 |
| 监控 | Prometheus 指标、Grafana 面板、审计日志 | 组织级面板、token 成本归属到部门、告警编排 |
| 服务 | 社区支持 | SLA、7×24、专属技术支持 |

企业版功能通过 trait 插件实现，核心代码中不出现企业版分支。定价单位待定（建议按席位 + Agent 数）。

**托管云（未决定）**：`tenant_id` 已经进入数据模型。托管云按合并后的消息计费，而不是按 token。HIPAA 的 BAA、数据驻留只对托管云有意义。

**风险**：Apache 2.0 允许任何人托管本项目。护城河来自迭代速度、社区、托管工具网关、合规认证和服务，而不是代码本身。
