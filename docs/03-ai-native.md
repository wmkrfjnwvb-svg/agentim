# 03 AI 原生能力

> 状态：草案 v0.1（2026-10-10）

## 1. 目标

**AI 可以与任何人、任何 AI 交流；人可以随时介入、过滤、监控。**

## 2. Agent 身份

- 每个参与者有身份类型：`human`、`agent`、`system`。
- Agent 必须有**所有者**（个人或组织）和**权限范围**（可加入哪些会话、可调用哪些工具、预算上限）。
- 消息记录"谁发的"（`sender_id`）和"代表谁发的"（`on_behalf_of`），委托关系可追溯。
- 支持四种会话形态：人与人、人与 AI、AI 与 AI、混合群聊。消息模型相同，区别只在策略。

## 3. 流式消息

| 规则 | 说明 |
|---|---|
| 开始即占位 | 流式回复在开始生成时分配一个 `conv_seq`，在会话中的位置就此固定 |
| 增量不消耗 seq | token 增量用 `(msg_id, chunk_idx)` 排序，不逐 token 写 Raft，批量落盘或结束时写入最终内容 |
| 版本号 | 流式结束、编辑、工具结果回填通过 `version` 更新同一条消息，客户端按版本覆盖 |
| 合并推送 | 首个 token 立即下发，后续在网关按 50–100ms 窗口合并 |
| 断线续传 | 重连后拿到当前已生成内容 + 继续接收增量；加载历史时拿到完整消息 |
| 取消与打断 | 用户或主管可中止流，Agent 收到取消事件 |

### 3.1 群聊流式

10 万人群里逐 token 推给所有人是灾难。规则：

- **增量只推给"正在看该会话"的人**（客户端进入会话界面时上报关注状态，网关维护会话级前台订阅）。
- 其他成员只在流式结束时收到最终消息的 seq 通知。
- Agent 在群里的发言频率和并发流数按群规模限流。

## 4. 人工介入

| 方式 | 含义 | 实现 |
|---|---|---|
| 观察 | 实时只读查看 Agent 会话，包括 AI 与 AI 的对话 | 主管对会话的只读订阅 |
| 耳语 | 给 Agent 发只有它可见的指导 | `visibility = agent_only` 的消息 |
| 审批 | Agent 的消息或工具调用先挂起，人批准后才发出 | 草稿区（见 4.1） |
| 打断 | 中止流式输出，插入人的消息 | 取消事件 + 普通消息 |
| 接管 | 暂停 Agent，人直接回复；结束后交还 | 会话级 Agent 状态锁 |
| 撤回/修订 | 发出后修改或撤回 AI 消息 | `version` 递增 / `state = recalled` |

### 4.1 审批与消息顺序

**待审批的消息不分配 `conv_seq`**，存放在单独的草稿区，仅审批人可见；批准后才写入会话日志并分配 seq；拒绝则直接丢弃，会话中不留空洞。审批模式下的流式输出只推给审批人。

## 5. 过滤

| 检查点 | 内容 |
|---|---|
| 进入 AI 之前 | 提示词注入检测（尤其来自其他 Agent 或外部用户的消息）、脱敏 |
| AI 输出之后 | 数据防泄漏、违规内容、可疑链接 |
| 流式过程中 | 按块检查；已推送内容被判违规时撤回整条消息并替换为提示 |

- 规则类过滤在分片内提交前同步执行；基于大模型的审核走异步队列，命中后通过撤回或审批处理。
- **纯人类会话默认不挂载 AI 钩子**，延迟不受影响；企业开启全局数据防泄漏时除外。

## 6. 监控

- 实时面板：活跃 Agent、进行中的流、token 消耗、错误率、策略命中。
- 会话回放。
- 审计：每个 Agent 动作（发消息、调工具、被审批、被接管）留痕。
- 告警：循环对话、预算超限、策略违规。

## 7. 安全护栏（免费版即具备）

| 风险 | 护栏 |
|---|---|
| Agent 互相对话死循环 | 每线程 Agent 跳数上限、重复内容检测、循环熔断 |
| 成本失控 | 单 Agent 速率限制与预算上限 |
| 提示词注入在群里放大 | 外部消息默认低信任等级、注入检测基础规则 |
| 刷屏 | 按群规模限制 Agent 发言频率与并发流数 |

## 8. 接入与互通

- **Agent SDK**：Agent 作为特殊客户端通过 WebSocket/QUIC 接入，与人类客户端同一协议。
- **Webhook**：适合无长连接的 Agent。
- **MCP Server**：内置，向外部 AI 暴露会话、历史检索、发消息等工具。
- **A2A**：后续通过网关支持跨平台 Agent 互通。
- **上下文 API**：带权限的历史检索，结果遵守会话可见性和成员范围。

## 9. 个人与企业的分层

原则：**个人能管好自己的 Agent，企业才需要管别人的 Agent。**

| 能力 | 社区版 | 企业版 |
|---|---|---|
| AI 交流 | 全部 | 同左 |
| 安全护栏 | 跳数、速率、预算、循环熔断、注入检测基础规则 | 自定义规则、组织级策略 |
| 人工介入 | Agent 所有者可观察、打断、接管、审批自己的 Agent | 主管跨团队观察、耳语、接管任意 Agent；多级、按风险路由的审批工作流 |
| 过滤 | 内置基础过滤器 + 可插拔接口 | 数据防泄漏、敏感数据脱敏、合规词库、外部审核服务接入 |
| 监控 | 单个 Agent 的用量和日志 | 组织级面板、会话回放、完整审计、告警、token 成本归属到部门 |
| 治理 | 单一 API Key | 按用户/组授权模型和工具、Agent 访问范围、提示词护栏 |
