<Capabilities>
- **不丢**：已确认的消息能扛过崩溃、重启、节点故障和数据库故障切换
- **有序**：每个成员看到同一串无空洞的序列；同一台设备的消息按发送顺序提交
- **恰好一次**：重试发送永远不会产生第二条消息
- **规则正确**：权限、可见性、审批和去重都由服务端执行
- **稳定**：过载时拒绝请求，而不是耗尽内存；慢设备伤不到别人
- **集群就绪**：从一个节点到多个节点，保证相同，协议也相同
</Capabilities>

## 每项保证具体是什么

| 保证 | 准确含义 | 怎么做到 |
|---|---|---|
| 不丢 | 只有写入落盘后服务端才确认；有副本时，要等副本也收到 | 提交后再确认；fsync 出错直接退出；等待副本；租约防护 |
| 有序 | 每个会话有一个只增不减、没有空洞、对每个成员都一样的 `seq`；同一个连接上的请求按顺序处理 | 每个会话一个写入者；`seq` 在事务内分配；先进先出扇出 |
| 恰好一次 | `(会话, 发送者, client_msg_id)` 和消息一起保存；重试返回第一次的结果。保留 7 天 | 同一个事务里去重 |
| 每台设备都收全 | 推送只是提示；每台设备从服务端为它记录的位置同步，所以丢失的推送会被补上，也不会重复 | 按设备记录位置；`resync` |
| 规则正确 | 请求到达时检查一次规则，在写入者的事务里再检查一次。被拒绝的请求什么都不写 | 业务规则目录；`agentim verify` 回放日志 |
| 稳定 | 所有队列都有上限。过载返回 `overloaded`，客户端重试；慢客户端只丢自己的推送并重新同步 | 有界队列；按数据库隔离故障 |

## 流式回复

流式回复在开始时就拿到 `seq`，所以位置不变。它的文字每秒保存一次；如果服务端在流式中途重启，消息以 `failed` 结束，保留到最后一次保存的文字，既不会消失，也不会重复。

## 不承诺的

- **跨会话的全局顺序。** 顺序以会话为单位。
- **信号的送达**，比如输入状态：它们只是实时的，从不存储。
- **推送给离线的设备。** 它回来后通过同步拿到全部内容（在保留期内）。
- **AgentIM 之外的循环。** 不通过会话、直接互相调用的 Agent，[安全护栏](/zh/docs/concepts/guardrails/)看不到。
