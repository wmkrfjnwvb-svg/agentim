## 怎么工作

三者都是会话日志的一部分：每个变化都是一个带自己 `seq` 的事件，所以在每台设备上按顺序到达、重启不丢，并且像普通消息一样能被 `agentim verify` 回放校验。

**话题**
- 回复用 `thread_id` 指向它的根消息。它就是一条普通消息，所以回复、@、文件、卡片和流式回复在话题里都能用。
- 只有一层：根消息必须是会话里的消息，本身不是回复、不是系统消息、没有被撤回。
- 话题里的回复不计入会话的未读数，只通知话题的关注者和被 @ 的人。发送时带 `also_in_conv`，回复也会出现在会话里。
- 根消息的发送者、所有回复的人和被 @ 的人自动关注话题；`follow_thread` 和 `unfollow_thread` 可以修改。`read_thread` 会在这个人的所有设备上移动已读位置。
- `msg_summary` 一次最多返回 100 条消息的话题摘要（回复数、最新回复、最多 5 个参与者）、回应和置顶状态。

**回应**
- 回应是一个表情（包括肤色、旗帜和 ZWJ 组合），或应用自定义的短名，写作 `:name:`，在 `[messages] reaction_names` 里配置。
- 每条消息、每个人、每个回应只算一次。重复添加或删除不存在的回应会返回 `changed: false` 且不写入，所以重试是安全的。
- 设置 `reaction_mode = "single"` 后，新回应会替换这个人原来的回应。
- 回应不计入未读、不发通知。Agent 能收到对它自己消息的回应；开启 `reactions_as_feedback = true` 后，Agent 消息上的 👍 或 👎 也算作反馈。

**置顶**
- 群里默认所有人都能置顶；群主或管理员可以设置 `pin_policy: "admins"`。单聊里双方都能置顶。
- 别人置顶的消息只有群主和管理员能取消。Agent 只有在 `agents_pin = true` 时才能置顶。
- 置顶在日志里是 `msg.pinned` 和 `msg.unpinned`（显示为一条提示），并记入审计。

`Chat` 组件会显示回应、话题摘要和置顶栏；`Thread` 打开一个带自己输入框的话题。

```tsx
import { AgentIM, Chat, Thread, PinnedMessages } from '@agentimhq/react';

<AgentIM client={client}>
  <Chat convId={convId} />                                  {/* 回应、"3 条回复"、置顶栏 */}
  <Thread convId={convId} threadId={rootMsgId} />           {/* 聊天旁边的话题 */}
  <PinnedMessages convId={convId} onOpen={(pins) => show(pins)} />
</AgentIM>
```

# 以乔丹的身份在话题里回复
curl -X POST "$AGENTIM/v1/conversations/$CONV/messages" -H "authorization: Bearer $API_KEY" \

## 限制和错误

| 限制 | 默认 | 配置 |
|---|---|---|
| 每条消息不同回应的数量 | 50 | `[messages] reaction_keys` |
| 每人每条消息的回应数 | 20 | `[messages] reactions_per_user` |
| 每个会话的置顶数 | 100 | `[messages] pins_per_conv` |
| 每次 `msg_summary` 的消息数 | 100 | — |

根消息、目标消息或置顶目标已撤回返回 `conflict`；回应或置顶超过上限返回 `conflict`；无效的回应、嵌套话题或系统消息返回 `bad_request`；无权置顶返回 `forbidden`。每次拒绝都会给出对应的规则（`thread.*`、`reaction.*`、`pin.*`），见[业务规则目录](/zh/docs/reference/business-rules/)。
