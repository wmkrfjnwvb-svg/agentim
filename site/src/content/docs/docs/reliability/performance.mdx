<Capabilities>
- 20,000 connections on one node, all dropped and back in about 2 seconds without a failed send
- End-to-end delivery p99 under 50 ms, even in a 2,000-member group at 100,000 pushes per second
- About 13.5 KB of server memory per open connection
- Back to ready about 130–240 ms after `kill -9`
- A slow reader is told to resync; everyone else misses nothing
- Every benchmark also checks correctness: gap-free, exactly once, in order
</Capabilities>

The numbers come from [`server/bench/`](https://github.com/wmkrfjnwvb-svg/agentim/tree/main/server/bench); run it on your own hardware for your numbers. The machine was a 4-core 2.1 GHz cloud VM with 15 GB of RAM, with the load generator on the same machine, and every acknowledgement waits for fsync. All tables are on the [benchmarks page](/benchmarks/).

## Connections and delivery

End-to-end is from the sender's send to each receiver's push.

| Scenario | SQLite | PostgreSQL | MySQL |
|---|---|---|---|
| 10,000 connections, groups of 100, 1% sending: p50 · p99 | 3 · 21 ms | 4 · 11 ms | 4 · 14 ms |
| All 10,000 dropped at once and reconnected (no message lost) | 1.0 s | 1.4 s | 1.4 s |
| Server memory per connection | 13.6 KB | 13.5 KB | 13.5 KB |
| 1,000-member group at 50 msg/s (50,000 pushes/s): p50 · p99 | 7 · 13 ms | 7 · 17 ms | 7 · 15 ms |
| 200-member group, 20 members stop reading, 2 KB messages: everyone else's p50 · p99 | 4 · 12 ms | 4 · 14 ms | 5 · 29 ms |
| Restart after `kill -9`, from process start to ready | 236 ms | 128 ms | 131 ms |

## Scale tests

On a standard CI runner, SQLite, each scenario sending for 120 s:

| Scenario | Result |
|---|---|
| 20,000 connections, then all dropped at once | Connected in 2.5 s and all back in 2.3 s, with no failed send. p50 3 ms, p99 7 ms; 2.4M deliveries, none lost or out of order |
| 2,000-member group, 50 msg/s (100,000 pushes/s) | 12M deliveries, all in order. p50 14 ms, p99 43 ms; server memory 54 MB |
| 500-member group, 50 members stop reading, 300 msg/s of 2 KB | The 50 are told to resync and catch up; the other 450 miss nothing: p99 30 ms; memory 34 MB |

## Sizing

| | Guide |
|---|---|
| Memory | about 13.5 KB per open connection: 10,000 people online is about 135 MB, before the database |
| Writes | about 1,100–1,300 messages per second per database today; conversations on different shards of a cluster write in parallel |
| Fan-out | pushes are cheap: each event is serialised once and shared |
| Recovery | a crashed node's conversations move after about 15–18 s; writes to them pause meanwhile |
| Limits | a message is at most 64 KB; a streamed message at most 256 KB and 10 minutes |
