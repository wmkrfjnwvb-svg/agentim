Every client SDK is a thin layer over one Rust core. The core holds all the rules: connecting and reconnecting, syncing without gaps, the offline queue, the encrypted cache and paging through history. So an app behaves the same on every platform, and a fix lands everywhere at once. Each wrapper runs the same scenario against a real server in CI.

Each SDK gives your UI three things to follow and methods that resolve once the change is on screen:

| | |
|---|---|
| `connection` | `closed`, `connecting`, `connected`, `disconnected`, `suspended` or `failed`, and why |
| `conversations` | The conversation list, newest first: title, members, unread count, last message |
| `messages(convId)` | One conversation's messages, oldest first, with `loadOlder()` and `hasOlder` |

## Platforms

| Platform | Package | Built on |
|---|---|---|
| Browser, Node | `@agentimhq/client-web` | The core in WebAssembly (146 KB gzipped), an encrypted IndexedDB cache, one connection shared by all tabs |
| React | `@agentimhq/react` | Hooks and components: chat window, conversation list, cards, files, themes, right-to-left |
| React Native | `@agentimhq/client-react-native`, `@agentimhq/react-native-ui` | JSI binding to the native core; components |
| iOS, macOS | `agentim-swift` (Swift Package) | `@Observable` state on the main actor, `async` methods |
| Android, JVM | `com.agentim:client` | `StateFlow`, `suspend` methods |
| .NET, Unity | `AgentIM.Client` (NuGet, OpenUPM) | `Observable<T>` and `Task` methods; Unity WebGL through the browser SDK |
| Flutter, Dart | `agentim_client` (pub.dev) | `Stream`s and `Future`s over FFI |

<TabItem label="Web">
```ts
import { AgentIMClient } from '@agentimhq/client-web';

const client = await AgentIMClient.create({
  url: 'https://chat.example.com',
  deviceId: (localStorage.deviceId ??= crypto.randomUUID()),
  tokenProvider: () => fetch('/api/chat-token').then((r) => r.text()),
});
await client.connect();

client.conversations.subscribe((list) => render(list));
const view = client.messages(convId);
view.subscribe((messages) => renderMessages(messages));
await client.send(convId, 'Hello!');
```

## Things every app should know

- **Keep the device id.** Generate it once and store it. A new id is a new device: it syncs from scratch and shows up as another device in the user's list.
- **`tokenProvider` is called often.** On the first connection, every reconnect and expiry. Make it cheap and let your backend decide. Throw `TokenRefused` when your backend says the user is signed out; the client then stops instead of retrying.
- **Sending never fails because of the network.** A message waits as `sending` until it can go. It becomes `failed` only when the server refuses it by its rules; then offer `retry` or `discard`.
- **Use `key` for list identity.** A message sent from this device is `local:<client_msg_id>` until the server's copy replaces it in one change.
- **`mine`** says whether I sent a message, from any of my devices. You don't need to know the server's internal user id.
- **Errors** carry a `code`: the server's (`forbidden`, `not_found`, `conflict`, `bad_request`, `blocked`, `rate_limited`, …) or the client's (`disconnected`, `timeout`, `closed`, `unauthenticated`). See [errors](/docs/reference/errors/).
- **`debugState()`** returns the connection, sync positions, queue and recent failures. Attach it to bug reports.
